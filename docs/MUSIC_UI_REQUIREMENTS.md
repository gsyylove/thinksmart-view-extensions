# 音乐与天气界面规格与实施记录

记录日期：2026-11-08。以下方案已实施并同步两台设备；最后按用户反馈将同排时间字号定为 20px。运行环境为半格系统层 0.2.1、客户端 0.1.6。

## 边界

- 原系统“待机”和“设置”的代码、样式和自身行为不变。
- 仅在天气、音乐扩展的 JS/CSS 中调整新增控件，尽量降低上游更新后的维护成本。
- 不改天气数据和音乐 API；除下述自动选歌规则外，保留现有播放逻辑。

## 顶部布局

- 从左到右：天气 → 音乐 → 待机 → 设置。
- 顶部控件垂直居中对齐；设置保持最右侧。
- 天气：高度 52px、圆角 17px，保留温度和天气摘要。
- 音乐：高度 40px、圆角 12px，固定宽度约 200px；播放时歌手、歌名只在按钮内部滚动，切歌不挤动相邻控件。
- 天气、音乐使用协调的蓝灰底白字和边框。

## 播放器操作栏

- 从左到右：QQ 音乐标题 → 播放列表 → 收起；操作按钮靠右。
- 播放列表、收起均为高度 40px、圆角 12px，统一字体、边框和间距。
- 播放列表作为主要操作，边框可稍亮；收起保持低调，放在最右侧。

## 进度条时间

- 进度条下方同一行排列：当前播放时间 → 上一首 → 播放／暂停 → 下一首 → 歌曲总时间；三个控制按钮居中，两侧时间左右对齐，字号 20px。
- 只显示数字分钟和秒，使用 `m:ss` 格式，例如左侧 `1:08`、右侧 `4:32`。
- 不加“已播放”“总时长”等文字，不增加复杂装饰。
- 播放及拖动进度时更新时间，保持左右对齐。

## 多首匹配自动选歌

- 点播歌手和歌名返回多首候选且没有明确匹配时，正常播报后直接播放排序第一首，不再弹窗等待手选。
- 其余候选保留为搜索播放队列，可在播放列表点选或切换下一首。
- 明确匹配的现有自动播放逻辑保留；没有结果或播放失败时继续正常提示，不额外猜测歌曲。

## 验证状态

- 已通过隔离浏览器的时间更新、拖动、时长未知、自动首选、多源播放队列及横竖屏测试。
- 使用当前上游 0.1.6 的真实静态页面核对 1280×800 顶栏：顺序正确，无重叠；天气/设置高 52px，音乐/待机高 40px。
- 已部署至两台验证设备，扩展文件 SHA256 一致；客户端和音乐服务正常，音乐账号登录保留。用户已确认最终时间字号；现场语音准确率、不同歌曲播放权限及长期运行仍需结合实际使用检查。

- 验证横竖屏布局、滚动长歌名和顶部空间，确保不遮挡原系统控件。
- 验证播放、暂停、切歌及拖动后两侧时间更新。
- 原系统控件未改样式或行为，改动均位于扩展文件。
