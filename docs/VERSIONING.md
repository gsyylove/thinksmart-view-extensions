# 组件版本与联合发布方案

音乐和天气独立编号，同一 Release 联合发布。

音乐和天气分别维护版本号，在同一个 GitHub Release 中发布。每个 Release 用一个组合标签固定仓库提交，并明确该提交包含的两个组件版本。

当前联合版本为音乐 0.1.1、天气 0.1.1，标签 `m0.1.1-w0.1.1`。

## 首次发布

| 项目 | 版本与标识 |
| --- | --- |
| 音乐扩展 | 0.1.0 |
| 天气扩展 | 0.1.0 |
| Git 标签 | m0.1.0-w0.1.0 |
| Release 标题 | 音乐 0.1.0 · 天气 0.1.0 |
| 已验证上游客户端 | 0.1.6 |
| 已验证上游系统层 | 0.2.1 |

`m` 表示 music，`w` 表示 weather。组合标签用于标识发布组合，两个组件本身分别使用三段版本号。上游系统层与客户端版本只作为兼容信息，不参与本扩展版本编号。

## 后续递增

- 仅音乐修复：音乐 0.1.1、天气 0.1.0，组合标签 m0.1.1-w0.1.0。
- 仅天气修复：音乐版本不变、天气修订号递增。
- 某组件新增功能：该组件次版本递增，例如音乐 0.2.0；另一个组件无改动则版本不变。
- 两个组件都变动：分别按各自实际变化递增。
- 仅文档修正不必为运行组件增加版本；如果修正随发布包交付，则使用新标签，不移动已发布标签或替换旧版本内容。
- 新增不兼容变化需在发布说明写清迁移方式；在公开安装及兼容承诺成熟前保持 0.x 阶段。

发布前将组件版本同步到对应模块 README、项目首页与更新记录；发布内容使用对应标签，避免把未来 main 分支变化混入已发布版本。

联合发布不影响单独安装：安装器仍支持 all、music、weather 三种目标。
